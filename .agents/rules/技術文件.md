# NAS 免空自動上傳系統 — 完整技術規範文件 (Technical Specification)

本文件詳細規範「NAS 免空自動上傳系統」的內部架構設計、核心模組分工、免空 API 互動機制、資料結構 schema 以及例外容錯處理。


1. 系統架構與設計理念

本系統專為 NAS 環境設計，採用單一循環主腳本 (Single Loop Script) 搭配歷史紀錄 JSON 檔 (history.json)，進行無資料庫 (Database-less) 的輕量化狀態追蹤。

1.1 核心工作流程
1. 監控與穩定度檢測：主程式 (main.py) 定期掃描 /watch 目錄，透過時間與檔案大小快取 (size_cache) 驗證檔案是否已完全寫入。
2. 狀態比對：讀取 data/history.json，檢查檔案在各平台的上傳狀態 (pending / success / skipped / failed) 以及是否已歸檔 (archived)。
3. 容量與每日限額檢查：
   - 呼叫 KatFile API 查詢剩餘儲存空間 (storage_left)。若空間不足則將狀態標記為 skipped。
   - 計算今日已上傳位元組總量，若加上新檔案超過每日限額 (預設 10GB)，則暫停該檔案至 KatFile 上傳，保持 pending 等待隔日重置。
4. FTP 循序上傳：對未完成平台依序進行 FTP 上傳 (KatFile: ftp.katfile.com, Rapidgator: upload.rapidgator.net)，避免多檔同時上傳擠爆 NAS 頻寬與 CPU。
5. API 連結擷取與輪詢：
   - KatFile: FTP 傳送後，輪詢 API 獲取檔案下載連結 (link)。
   - Rapidgator: 登入取得 sid 後，輪詢 API 抓取 file_id 並組合成標準下載連結。
6. 連結紀錄與 CSV 導出：
   - 將下載連結寫入 data/links.txt 文字紀錄。
   - 呼叫 csv_exporter.py，將檔案標題、動態轉化的大小 (MB/GB) 與雙免空連結帶入 config.yaml 中的 post_template 範本，寫入 data/posts.csv。
7. 歸檔與狀態更新：雙平台處理完畢後，將檔案從 /watch 移動至 /completed 歸檔資料夾，並將 history.json 中的 archived 設為 true。


2. 資料結構規範 (Data Schemas)

2.1 歷史紀錄檔 (data/history.json)
{
  "files": {
    "sample_video.mp4": {
      "size": 1073741824,
      "added_at": "2026-08-15 20:00:00",
      "katfile": {
        "status": "success",
        "link": "https://katfile.com/example123/sample_video.mp4.html",
        "error": null
      },
      "rapidgator": {
        "status": "success",
        "link": "https://rapidgator.net/file/abc123/sample_video.mp4.html",
        "error": null
      },
      "archived": true,
      "archived_at": "2026-08-15 20:05:00"
    }
  },
  "daily_stats": {
    "2026-08-15": {
      "katfile_uploaded_bytes": 5368709120
    }
  }
}

2.2 發文 CSV 檔案規格 (data/posts.csv)
- 編碼格式：UTF-8-SIG 帶 BOM（確保 Excel 開啟中文不亂碼）。
- 欄位定義：
  - file_name: 完整原始檔名 (例: video.mp4)
  - title: 自動去除副檔名後之標題 (例: video)
  - content: 套用 post_template 發文模板後之內文 (含 BBCode/Markdown 下載連結與解壓密碼說明)
  - katfile_url: KatFile 下載連結 (若跳過或失敗則填寫 "無")
  - rapidgator_url: Rapidgator 下載連結 (若跳過或失敗則填寫 "無")
  - created_at: 產生時間 (YYYY-MM-DD HH:MM:SS)
  - status: 發文狀態，預設為 "Pending" (發文後可手動改為 "Posted")


3. 模組架構與函數規範

3.1 src/main.py (主控制與調度模組)
- load_config(): 載入 config/config.yaml 設定檔。
- load_history() / save_history(): 讀寫 data/history.json，包含自動修復與建立基礎結構。
- check_file_stable(file_path, stable_time, size_cache): 利用 size_cache (紀錄 last_size 與 last_time) 判斷檔案是否已停止寫入。每次迴圈會自動清理失效快取防止記憶體洩漏。
- get_katfile_storage_left(api_domain, api_key): 呼叫 https://{api_domain}/api/account/info?key={api_key} 取得剩餘容量。
- get_katfile_uploaded_today(history) / add_katfile_uploaded_today(history, file_size): 讀寫今日上傳累計 Bytes。
- upload_to_katfile_ftp() / upload_to_rapidgator_ftp(): 使用 ftplib 上傳檔案至平台，設有 60 秒 Timeout 護航。
- get_katfile_download_link(): 輪詢 KatFile API (/api/file/list) 匹配檔名取得下載連結 (最多重試 6 次，間隔 15 秒)。
- get_rapidgator_sid() / get_rapidgator_download_link(): 登入 Rapidgator 取得 sid，輪詢 /api/folder/content 獲取 file_id 並組合連結。
- write_link_to_txt(): 將結果追加寫入 data/links.txt。
- process_file(): 核心調度邏輯，依序執行限制檢查、FTP 上傳、API 查詢、CSV 導出與檔案移動歸檔。

3.2 src/csv_exporter.py (CSV 發文匯出模組)
- format_size(size_bytes): 將位元組精確格式化為易讀字串 (例: "1.05 GB", "500 MB")。
- get_filename_without_ext(filename): 提取檔案名稱（去掉副檔名）作為預設文章標題。
- export_to_csv(csv_path, filename, file_size, kat_link, rg_link, template): 帶入 {title}, {file_size}, {katfile_url}, {rapidgator_url} 變數格式化發文內文，並寫入/追加至 posts.csv。


4. 容器部署與路徑對照

使用 Docker Compose 單一目錄對應 (. -> /app) 部署：
- . (專案根目錄) ---> /app (容器工作目錄)
- NAS 暫存區 (如 /share/.../watch) ---> /watch (監控資料夾)
- NAS 歸檔區 (如 /share/.../completed) ---> /completed (歸檔資料夾)
