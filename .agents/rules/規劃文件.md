NAS 免空自動上傳與收益系統 — 規劃文件

本文件詳細規劃了在 NAS 環境下運作的「免空自動上傳系統」的架構與任務分工。


1. 系統架構設計

為了讓系統保持輕量、穩定且易於維護，我們捨棄複雜的資料庫與多執行緒佇列，改用單一循環主腳本 (Single Loop Script)，搭配一個輕量 JSON 狀態檔（history.json）來追蹤上傳與論壇發文進度。

運作流程：
1. 偵測並確認檔案寫入完畢 -> 主程式 (main.py)
2. 讀取與比對狀態 -> 歷史紀錄檔 (history.json)
3. 檢查容量與每日限額 -> 檢查 KatFile 空間 & 每日 10GB 限額
4. 依序上傳 FTP -> KatFile & Rapidgator
5. 呼叫 API 取得連結 -> 免空 API
6. 紀錄連結 -> 下載連結檔 (links.txt)
7. 歸檔移動 -> NAS 完成資料夾 (/completed)
8. 將影片的標題以及內文寫進csv檔案
9. 手動登入與發文 -> 目標論壇 (如 eyny, reddit 論壇)

這個簡化架構的優勢：
- 無資料庫依賴：完全使用輕量 history.json 記錄每個檔案在上傳各平台的狀態（例如 KatFile: 成功, Rapidgator: 待上傳, CSV寫入: 待處理），避免資料庫毀損風險。
- 支援平台間續傳：若上傳 KatFile 達到每日 10GB 上限，Rapidgator 與 CSV 寫入仍會繼續執行。隔天額度恢復後，會自動補上傳 KatFile，完成後才將檔案移到完成區。
- 單執行緒循序處理：檔案一個接著一個上傳，避免多檔案同時上傳榨乾 NAS 網路與 CPU 資源。
- 降低發帖複雜度：先將整理好的影片標題、內文與免空下載連結寫入 CSV，由使用者後續進行手動/半自動發文，徹底避開論壇複雜驗證碼（CAPTCHA）與 Cloudflare 防爬蟲機制，並防堵自動化發帖導致的封號風險。


2. 任務切分與實作步驟

階段一：基礎環境建置與設定檔設計
- 1.1 初始化專案結構：建立 src/、config/ 與 .agents/rules/ 目錄。
- 1.2 設計設定檔 (config.yaml)：定義免空 API 金鑰、FTP 帳密、掃描間隔、每日上傳限額，以及 CSV 發文範本格式。
- 1.3 撰寫 Docker 部署檔：Dockerfile 與 docker-compose.yml。

階段二：監控與歷史紀錄讀取 (main.py)
- 2.1 掃描資料夾：讀取 /watch 下的檔案。
- 2.2 穩定度檢測：比對檔案大小，確認沒有人在寫入後才開始處理。
- 2.3 讀取與初始化 history.json：載入歷史紀錄，判斷該檔案在各平台（KatFile / Rapidgator / CSV寫入）的完成狀態。

階段三：限制檢查、上傳、API 抓取與歸檔
- 3.1 空間與每日限額檢查：
  - 呼叫 KatFile API 查詢剩餘空間。
  - 讀取今日已上傳總量，若加上目前檔案會超過 10GB，則暫停該檔案上傳至 KatFile，直到明日額度重置。
- 3.2 FTP 上傳：依序將檔案上傳至尚未完成且空間與額度允許的平台。
- 3.3 API 連結獲取：呼叫免空 API（例如 katfile.biz API）抓取對應的下載連結。
- 3.4 紀錄下載連結：將生成的免空連結寫入 links.txt，更新 history.json 中的上傳狀態。

階段四：發文 CSV 產生與歸檔
- 4.1 設計 CSV 欄位結構：
  - 欄位定義：file_name,title,content,katfile_url,rapidgator_url,created_at,status
  - 說明：content 欄位會根據 config.yaml 內定義之發文模板（BBCode/Markdown），自動將檔案資訊與下載連結套入組合。status 預設為 Pending，供使用者手動發文後標記為 Posted。
- 4.2 開發 CSV 導出模組 (csv_exporter.py)：自動提取影片名稱資訊並將所有下載連結與發文樣板組裝後寫入 /app/data/posts.csv。
- 4.3 主程式整合與歸檔：當 history.json 顯示某一檔案的所有免空皆上傳成功後，主程式呼叫 csv_exporter.py 寫入 CSV，完成後將檔案從 /watch 移動到歸檔資料夾 /completed。

  說明：包含 src/ (程式)、config/ (設定)、data/ (歷史紀錄與 posts.csv)，程式與設定修改免 rebuild

- 專案相對路徑 / NAS 實體路徑：NAS 影音歸檔區 (如 /share/.../completed)
  容器內對應路徑：/completed
  說明：上傳且 CSV 寫入完成後，檔案自動移動至此歸檔
